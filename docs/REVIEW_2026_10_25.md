# Review before replacing the legacy main branch

Scope: the current implementation replacing the older application in `aimadhav/gstrag`. Targeted manual review covered admin PDF transfer/staging, review and publication gates, replacement/citation retention, current-role authorization, Pinecone snapshot/namespace checks and the opt-in notification scheduler. Automated checks covered the full current test suite. This is not an independent security or legal audit.

## Findings

No blocking defect was identified in the reviewed workflows. The following small portability issues were corrected before the push:

- Two offline source-audit helpers hardcoded one Windows username. They now resolve the current user's Downloads folder with `Path.home()`; original source documents are still required locally and are not redistributed.
- The earlier experiment-repair guide linked to absolute machine-local source paths. Source/test links now use repository-relative paths, and its private diagram supplement is explicitly described as an uncommitted local artifact.

No benchmark settings, frozen evidence, ingestion decisions or measured results were changed by those fixes.

## Verification

- 360 Python tests pass.
- 67 frontend tests pass.
- Frontend TypeScript/production build passes.
- Candidate-file scanning found no known-format API tokens or private-key blocks. This is a pattern check, not a guarantee that every possible secret format is detected.
- `.env`, source PDFs/DOCX files, `data/`, generated `output/`, `.archive/`, environments, `node_modules` and build output are excluded from the commit. Public fixture passwords in tests/scripts are intentionally disposable, not real account credentials.
- No live provider indexing, real-source approval, hosted deployment or schedule enablement was performed for this review.

## Known limits retained

Unknown PDF layouts still need human inspection; the upload interface has no OCR or chunk-repair editor. Parsing is a trusted-admin, single-host worker, not a resource-isolated production sandbox. Gemini's live behavior, legal correctness and complete/current GST coverage are not established by these tests. See the [upload milestone](BACKEND_07_PDF_UPLOADS.md) and [project brief](PROJECT_BRIEF.md).

## Repository replacement

The replacement removes obsolete tracked application files from the current `main` tree, not from historical commits. The previous implementation remains recoverable through Git history. Only source, tests, configuration templates and documentation are included; no local user data is deleted or uploaded.
